# 实习经历

## 1. 智慧渔业方向｜售前工程师实习

**实习时间：** 2026.04 - 2026.08  
**所属行业：** 智慧渔业 / 水产养殖数字化 / 无人机巡检  
**岗位方向：** 售前工程师

---

## 2. 实习背景

实习期间主要参与智慧渔业、水产养殖数字化以及无人机巡检等方向的售前支持工作。

工作内容覆盖从前期客户需求理解，到技术方案设计、设备选型、供应商沟通、招投标文件编制，再到部分项目实施阶段的问题跟进。

这段经历让我第一次比较系统地接触到政企项目中的完整售前工作流程：

`客户需求 → 需求拆解 → 技术调研 → 方案设计 → 设备选型 → 供应商询价 → 标书制作 → 投标响应 → 项目实施协同`

相比单纯完成某一个技术任务，售前工作更需要站在客户、产品、技术、商务和交付多个角度之间进行协调。

---

## 3. 技术方案与需求分析

实习期间参与多个智慧渔业相关项目的需求分析和方案编制。

其中一个水产养殖数字化管理平台项目，客户希望通过数字化平台实现养殖生产、数据采集、监管管理和可视化展示。

在项目过程中，我主要参与：

- 梳理养殖监管、生产管理、数据采集等业务场景
- 根据客户需求拆解平台功能
- 参与技术方案相关章节编写
- 根据招标文件评分项调整技术方案结构
- 将客户需求与产品能力进行对应
- 配合完成项目技术响应

在这个过程中，我逐渐理解了一份售前技术方案并不是简单介绍公司产品，而是需要建立：

`客户痛点 → 业务需求 → 功能设计 → 技术方案 → 项目价值`

之间的完整逻辑。

该项目最终顺利完成投标并成功中标。

---

## 4. 无人机巡检方案调研

实习期间参与多个无人机巡检相关项目。

其中一个典型需求是：

客户希望无人机完成自动巡检，同时具备边缘计算识别能力，并将实时视频接入客户已有的第三方管理平台。

最初客户给出的需求比较偏业务描述，因此首先需要将需求进一步拆解。

我将需求整理为：

- 无人机续航能力
- 自动巡航与航线管理
- 视频采集
- 边缘计算识别
- 异常事件预警
- 实时视频推流
- 第三方平台对接
- 地理位置展示
- 巡检路线展示
- 现场喊话

之后针对不同实现方式进行了方案调研。

主要比较：

`原厂无人机管理平台 / 第三方适配平台 / RTMP 视频推流方案`

比选过程中重点关注：

- 项目成本
- 功能完整度
- 系统兼容性
- 第三方平台开放能力
- 后续扩展能力
- 项目实施难度

同时与设备供应商沟通具体产品能力、接口方式和报价情况，为最终方案选择提供参考。

通过这类项目，我逐渐形成了一个比较清晰的需求分析过程：

`客户描述 → 业务需求 → 技术指标 → 产品能力 → 方案比选 → 推荐方案`

## 5. 招投标文件编制

实习期间还承担了较多招投标相关工作。

独立或协助完成过多份项目投标文件，主要包括：

- 商务文件整理
- 技术方案编制
- 技术参数响应
- 产品参数匹配
- 报价清单整理
- 资质文件检查
- 投标文件整体排版与检查

其中一个项目包含 **400+ 项报价及产品参数**。

我的主要工作是逐项检查：

- 产品品牌与型号是否一致
- 技术参数是否满足招标要求
- 报价清单与技术响应是否一致
- 产品名称是否前后一致
- 参数描述是否存在歧义
- 资质材料是否完整

在参数响应过程中，我也逐渐认识到招投标文件中的一些细节可能直接影响项目结果。

例如：

`≥ / ≤ / 不低于 / 不高于 / 大于 / 小于`

这些看似简单的参数描述，如果理解或响应错误，都可能造成技术参数不满足要求。

因此，在后续标书制作过程中，我会更加关注：

`参数一致性 → 资质完整性 → 响应准确性 → 文件完整性`

## 6. 投标风险复盘

在参与某展厅建设类项目投标过程中，接触到了一次因资质材料问题产生的投标风险。

项目结束后，我对整个过程进行了复盘。

其中一个比较重要的认识是：

招投标工作不能只关注技术方案和报价，还必须提前检查产品相关资质。

例如：

- 节能认证
- 3C 认证
- 产品检测报告
- 厂商授权
- 项目业绩
- 企业资质
- 产品相关证明文件

因此，在后续项目中逐渐形成了 Checklist 思维。

在正式制作投标文件之前，优先检查：

`项目资格条件 → 产品资质 → 企业资质 → 技术参数 → 商务材料 → 报价文件`

这能够尽量减少因为形式审查或材料遗漏造成的无效投标风险。

## 7. 项目现场调研

实习期间参与过一次水产行业相关项目的现场调研。

项目涉及利用图像识别技术识别不同类型的渔网和渔具。

为了获取真实业务场景中的数据，我前往沿海地区进行现场素材采集。

现场接触和整理的渔具类型包括：

- 拖网
- 流刺网
- 围网
- 张网
- 蟹笼
- 钓渔具

除了拍摄和整理素材之外，也与现场人员沟通不同网具的使用方式和实际识别难点。

这次经历让我更加直观地认识到：

AI 项目中的“数据”并不仅仅是算法训练集。

在真实项目中，需要先理解业务对象和实际使用环境，才能判断：

- 应该采集什么数据
- 哪些类别容易混淆
- 哪些场景需要重点采集
- 数据是否能够真实覆盖业务环境

因此，一个 AI 项目的流程实际上更接近：

`业务理解 → 数据采集 → 数据整理 → 模型训练 → 结果验证 → 业务应用`

## 8. 海水养殖设备问题跟进

在某海水养殖项目中，现场部分传感器和阀门设备出现腐蚀速度较快的问题。

由于海水环境具有高湿、高盐雾等特点，设备长期运行后容易影响可靠性。

针对这一问题，我协助客户和供应商进行方案沟通。

主要讨论了两类解决思路。

### 方案一：加强设备防护

通过增加耐腐蚀防护结构，提高现场设备的环境适应能力。

需要重点考虑：

- 防护效果
- 材料成本
- 安装方式
- 后期维护

### 方案二：减少现场暴露设备

减少部分现场显示设备，将传感器数据通过 RS485 等通信方式传输到集中控制设备。

基本结构为：

`传感器 → RS485 → 集中采集设备 → 管理平台`

相比单纯加强外壳防护，这种方式能够减少部分电子设备直接暴露在恶劣环境中的时间。

后续协助供应商进一步进行现场测试和方案验证。

这次问题处理让我认识到，售前在项目实施阶段同样需要参与：

`现场问题 → 原因分析 → 多方案比较 → 供应商验证 → 成本评估 → 现场测试`

---

## 9. 供应商沟通与方案选型

售前项目中很多设备和技术能力并不是公司完全自研，因此供应商沟通也是实习期间比较重要的一部分。

实际工作中经常需要：

- 根据客户需求寻找合适供应商
- 向供应商说明项目场景
- 获取产品技术参数
- 确认设备功能边界
- 询问接口及通信协议
- 获取设备报价
- 比较多个供应商方案
- 判断方案是否能够满足客户需求

这个过程中，我逐渐发现：

供应商提供的是“产品能力”，而售前需要考虑的是“项目是否能落地”。

因此不能只问：

`这个产品有什么功能？`

更需要进一步确认：

`这个功能能不能满足当前客户的实际使用场景？`

## 10. 工具与自动化

除了方案和投标工作之外，实习过程中也会接触一些重复的数据整理任务。

例如部分平台需要定期更新水产价格数据。

针对重复性的更新工作，我尝试使用 Python 编写简单脚本进行数据处理和自动化更新。

虽然这类工作技术难度不高，但让我认识到：

售前工程师掌握一定的编程能力，可以帮助提升很多日常工作的效率。

例如：

- Excel 数据批量处理
- 产品参数整理
- 报价数据检查
- 文档内容处理
- 数据格式转换
- 重复任务自动化

## 11. 能力沉淀

经过这段售前实习，我对售前工程师的理解从最初的“写方案、做 PPT”逐渐变成了一个更加完整的角色。

我认为售前工作主要需要连接几个角色：

`客户 ↔ 销售 ↔ 产品 ↔ 技术 ↔ 供应商 ↔ 交付`

在这个过程中，售前需要同时具备：

### 需求分析能力

能够从客户相对模糊的描述中提取真正的业务需求。

### 技术理解能力

能够理解物联网、通信、AI、边缘计算、平台对接等技术，并判断其在实际项目中的应用方式。

### 方案设计能力

能够将不同产品、设备和技术组合成完整解决方案。

### 文档表达能力

能够通过技术方案、架构图、参数表和 PPT 将复杂方案表达清楚。

### 招投标能力

理解政府和企事业项目中的招投标规则，并能够完成技术响应、参数检查和材料准备。

### 沟通协调能力

能够在客户、供应商以及公司内部团队之间同步需求并推动问题解决。

---

## 12. 实习总结

这段实习让我第一次比较系统地了解售前工程师从项目早期到实施阶段的工作内容。

我参与的工作可以概括为：

`需求调研 → 需求分析 → 技术调研 → 方案设计 → 供应商比选 → 设备选型 → 报价询价 → 招投标 → 项目协同 → 问题跟进`

相比单纯掌握某一种技术，我认为售前工程师更重要的能力是：

**理解客户的问题，并利用合适的产品和技术组合形成一个能够真正落地的解决方案。**
